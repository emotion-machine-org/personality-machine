# Pre-commit Setup Guide

## Quick Start

To install pre-commit run `brew install pre-commit`

## Commit without running pre-commit
You can use `git commit . -m 'conventional commit message' --no-verify` to bypass pre-commit
If you commit using an editor you can choose not to run git hooks or verify whathever option is available in your editor
However using these tools make engineers think about what best-practices they might have missed in their commits

## What Happens on Commit

When you run `git commit`, these checks run automatically:

### 1. General File Checks
- ✅ Removes trailing whitespace
- ✅ Ensures files end with a newline
- ✅ Validates YAML and JSON syntax
- ✅ Checks for merge conflicts
- ✅ Prevents large files (>1MB)
- ✅ Fixes line endings to LF

### 2. Python/Server (`server/` directory)
- ✅ **Ruff Format**: Auto-formats Python code
- ✅ **Ruff Lint**: Checks and auto-fixes linting issues
  - Configured in `server/pyproject.toml`
  - Includes: pycodestyle, Pyflakes, isort, flake8-bugbear, and more

### 3. TypeScript/JavaScript (`web/` directory)
- ✅ **ESLint**: Checks and auto-fixes TypeScript/JavaScript issues
  - Uses Next.js config
  - Configured in `web/eslint.config.mjs`
  - Max warnings: 0 (all warnings treated as errors)

## Manual Commands

### Run All Hooks (without committing)
```bash
# Run on staged files only (recommended)
pre-commit run

# Run on all tracked files (may include build directories if not properly gitignored)
pre-commit run --all-files

# Note: --all-files is mainly for testing. During normal commits,
# pre-commit only checks staged files, which excludes directories such as node_modules/
# and .next/ because they're in .gitignore
```

### Run Specific Hook
```bash
pre-commit run ruff --all-files          # Python linting
pre-commit run ruff-format --all-files   # Python formatting
pre-commit run eslint --all-files        # TypeScript/JavaScript linting
```

### Update Hook Versions
```bash
pre-commit autoupdate
```

### Skip Hooks (Emergency Only)
```bash
git commit --no-verify
```
⚠️ **Not recommended** - only use for WIP commits

## Project-Specific Linting

### Web (Next.js/TypeScript)
```bash
cd web
npm run prelint     # Auto-fix and check
npm run lint        # Check only
npm run lint:fix    # Auto-fix
```

### Server (Python/FastAPI)
```bash
cd server
uv run ruff format .           # Format code
uv run ruff check .            # Check for issues
uv run ruff check . --fix      # Auto-fix issues
```

## Troubleshooting

### Hook Installation Issues
If hooks don't run on commit:
```bash
pre-commit install
```

### Clean Cache and Reinstall
```bash
pre-commit clean
pre-commit install --install-hooks
```

### Check Hook Status
```bash
pre-commit run --all-files --verbose
```

### ESLint Not Finding Dependencies
If ESLint fails, make sure web dependencies are installed:
```bash
cd web && npm install
```

## Configuration Files

- `.pre-commit-config.yaml` - Hook configuration (repo root)
- `server/pyproject.toml` - Ruff configuration
- `web/eslint.config.mjs` - ESLint configuration
- `web/package.json` - ESLint scripts

## CI/CD Integration

Pre-commit hooks run locally before commits. For CI/CD:

**GitHub Actions Example:**
```yaml
- name: Run pre-commit
  run: |
    pip install pre-commit
    pre-commit run --all-files
```

## Best Practices

1. **Commit often** - Hooks run faster on fewer files
2. **Stage incrementally** - Use `git add -p` for partial staging
3. **Fix, don't skip** - Address issues rather than using `--no-verify`
4. **Keep updated** - Run `pre-commit autoupdate` monthly
5. **Review auto-fixes** - Check changes before committing

## Hook Execution Order

1. File checks (whitespace, EOF, YAML/JSON)
2. Ruff format (Python formatting)
3. Ruff lint (Python linting)
4. ESLint (TypeScript/JavaScript)

If any hook fails or modifies files:
- Files are updated in place
- You must stage the changes
- Re-run `git commit`
